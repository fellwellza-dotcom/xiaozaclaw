# 小扎中小企业实用化路线

## 产品判断

小扎当前的核心价值是可靠地连接 Windows 节点、Gateway、MCP 和本地能力。它
适合技术人员部署和维护，但对中小企业的一线员工而言，入口仍然偏向模型、节点、
权限和诊断等技术概念。

对照 `claw1`，其更容易被普通用户采用的原因是把模型、渠道、Agent、技能、定时
任务、备份和日志组织为可见的管理闭环。小扎不应复制其桌面管理台，而应在保留
Windows 本地能力和安全边界的基础上，补齐企业中的人、事、知识、权限和交付闭环。

产品定位调整为：

> 面向 10 至 300 人团队的 AI 工作台。员工用模板完成日常工作，管理员用清晰的
> 规则、审批和记录控制风险，IT 不需要成为每个任务的操作员。

## 首批目标用户

| 用户 | 要完成的事 | 当前主要阻碍 | 一期结果 |
| --- | --- | --- | --- |
| 普通员工 | 写周报、整理会议、生成客户跟进、查询制度 | 不理解 Agent、渠道和模型 | 从工作模板开始，提交后获得可编辑结果 |
| 部门主管 | 分派重复工作、审核对外内容、了解执行状态 | 没有任务队列和交付记录 | 能看到待审核、失败和已交付任务 |
| 企业管理员 | 配置成员、权限、知识、预算和连接 | 运维入口与业务入口混在一起 | 管理员专区集中处理设置、审计和异常 |
| IT 或实施人员 | 部署、接入 Windows 能力、排查故障 | 需要在业务界面中筛选技术信息 | 保留现有节点、MCP、诊断和恢复能力 |

## 信息架构

默认给普通员工展示四个一级入口：

1. 工作台：新建工作、模板、最近交付和待处理事项。
2. 我的任务：执行中、等待补充、待确认、已完成和失败任务。
3. 团队知识：企业制度、产品资料、客户资料和部门 SOP 的来源与更新状态。
4. 帮助与反馈：使用指引、常见问题和人工支持入口。

管理员额外看到“管理中心”，其中包含成员与角色、业务模板、审批规则、连接与渠道、
Windows 能力、审计与用量、备份与诊断。模型、MCP、Sandbox、原始日志不再占据
普通员工的默认导航，仍完整保留在管理中心的高级设置中。

## 分期改造

### P0：可用的企业工作台，2 至 3 周

目标是让一家公司能在当天完成部署、邀请首位员工，并交付第一个可审核的结果。

| 优先级 | 交付项 | 验收标准 |
| --- | --- | --- |
| P0 | 企业初始化向导 | 管理员完成企业名称、部门、首位管理员、默认数据策略和一项连接配置，不要求理解 Gateway 或 MCP |
| P0 | 工作模板中心 | 内置会议纪要、日报周报、客户跟进、制度问答、表格整理五类模板。模板要求输入项、可选知识范围和结果格式 |
| P0 | 任务与交付记录 | 每次执行都有状态、负责人、输入摘要、结果、失败原因和可重试入口。员工仅能查看自己有权限的任务 |
| P0 | 角色与审批 | Owner、管理员、成员、只读四级角色。对外发送、文件写入、Windows 自动化默认进入审批队列 |
| P0 | 管理员概览 | 展示活跃成员、待审批、失败任务、连接健康和近 7 天用量，不展示原始技术日志作为首要信息 |

P0 不引入复杂的流程画布、CRM 或多租户 SaaS。先让一个团队稳定跑通“选模板，
补信息，执行，审核，交付，留痕”的闭环。

### P1：让团队重复使用，3 至 5 周

- 团队知识库：支持文件夹、网页、Markdown 和表格导入，标明来源、负责人、更新时间和可见部门。
- 模板配置器：管理员可以复制内置模板，定义表单字段、输出格式、可用知识、可调用工具和审批条件。
- 邀请与组织：邀请码或链接邀请成员，部门分组，离职成员移交任务和停用权限。
- 任务通知：通过已接入的企业 IM 推送待审批、失败、交付和需要补充的信息。
- 用量治理：每个部门和模板设定月度预算、模型等级和超额提醒。

### P2：连接企业现有业务，6 至 10 周

- 先提供可维护的 CSV、Excel 和邮件附件导入导出，再评估 CRM、ERP、OA 和客服系统连接器。
- 提供线性流程编排：触发条件，收集信息，AI 处理，人工审批，发送或写入。每一步可追溯。
- 为常见岗位提供成套方案：销售跟进、行政制度助手、客服质检、财务单据整理、IT 服务台。
- 支持本地部署备份、保留期限、审计导出和管理员恢复演练。

## 实施原则

1. 先交付岗位结果，不先暴露技术能力。员工看到的是“客户跟进”，而不是“选择 Agent”。
2. 高风险动作默认可见、可审、可撤销。审批只拦截对外发送、写文件、运行系统命令等动作。
3. 复用现有 Gateway、节点连接管理和 MCP 安全边界。业务层使用窄服务和独立数据模型，不把企业工作流重新塞进 `App` 或连接页。
4. 每个新入口都必须覆盖空状态、失败状态、权限不足和首次使用引导。
5. 以离线优先和本地可控为默认。只在管理员明确配置时使用外部模型或外部连接器。

## 一期数据与安全边界

一期新增的业务记录最小集合为：企业配置、成员角色、模板版本、任务、审批、交付物、
审计事件和用量汇总。凭据、原始提示词、文件正文、模型原始响应和系统命令输出不能
写入遥测。任务详情按角色和部门隔离，审计记录只记录必要的操作者、动作、对象、
时间和结果。

## 衡量是否真正实用

P0 上线后，以一个 10 至 30 人试点团队为准，四周内达到：

- 管理员从安装到邀请第一名成员不超过 20 分钟。
- 新员工在没有技术培训的情况下，5 分钟内完成首个模板任务。
- 至少 70% 的任务由模板发起，而非直接进入底层聊天或设置页。
- 高风险任务的审批记录覆盖率为 100%。
- 任务失败能在页面内说明原因并给出下一步的比例达到 95%。

## 首个开发切片

建议以“会议纪要到待审核交付”为第一条纵向链路：

1. 管理员创建或启用“会议纪要”模板。
2. 员工粘贴会议记录或上传受支持文件，选择可见范围。
3. 系统创建可追踪任务，调用现有 Gateway 和模型能力。
4. 结果进入员工确认或主管审批。
5. 审批后生成可复制、导出或发送到已授权渠道的交付物，并写入审计记录。

这条链路同时验证模板、任务、权限、审批、交付、审计和现有节点能力的整合方式，
应作为后续所有企业场景的基线。
